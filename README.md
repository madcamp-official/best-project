# 구청장 시뮬레이터 — 실제 지도 기반 실시간 영토 점령 게임

> **이 문서의 용도**: 게임의 현재 사양서. 서술형 기획 의도가 아니라 "무엇이 구현되어 있는지"에 초점.
> 수치·규칙의 최종 진실은 코드다 — 밸런스 값은 `web/src/config.ts`(클라)와 `server/.../config/GameConfig.kt`(서버)가
> 원본이며 두 파일은 항상 동기를 유지한다(convention §5 "코드가 기준"). 절대값은 계속 튜닝 중이므로, 특정 상수의
> 현재 값이 필요하면 코드를 본다.
>
> **레퍼런스**: 실제 한국 시/군/구 지도 × state.io(영토 점령) × io류 멀티플레이(방·라운드) + 부족 인원을 채우는 AI.

관련 문서: [아키텍처](docs/architecture.md) · [프로토콜(API)](docs/api-spec.md) · [코드 컨벤션](docs/convention.md) · [웹 클라](web/README.md) · [서버](server/README.md)

## 0. 게임 개요

- **지도**: 대한민국 **시/군/구 250개**가 점령 단위(셀)다. 실제 행정 경계(`kr-sgg.geojson`) 위에서 플레이한다.
- **목표**: 인접 셀로 병력을 보내 영토를 넓히고, **전국 51% 점유(도미네이션)** 또는 **제한 시간(30분) 종료 시 1위**로 라운드에서 승리한다.
- **PvP + AI**: 한 방(세션)에 **최대 8명**이 경쟁한다. 사람이 8명에 못 미치면 부족분을 **AI가 채운다**(AI도 확장·증원으로 자연스러운 전선을 만든다).
- **계급**(셀 소유 수에서 파생): 셀 1개 이상 **구청장**, 5개 이상 **시장**, 어떤 시/도를 전부 장악하면 **도지사**, 전국 40% 점유 시 **대통령**.
- **멀티플레이**: 로비에서 방 생성/입장 → 대기실(방장 시작·준비 시스템) → 라운드 → 결과 → 로비. 서버(Spring Boot/STOMP)가 권위, 클라는 렌더러+입력 전송기.

## 1. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 클라 빌드 | Vite 6 + React 19 + TypeScript | oxlint 린트, `tsc -b` 타입 체크 |
| 지도 | MapLibre GL JS 6 | `setFeatureState`로 소유권 색칠, CARTO 다크 베이스맵 |
| UI 상태 | Zustand 5 | 소량만(선택 셀·HUD·로비). 셀 배열은 React 밖 |
| 게임 상태 | typed array (`Uint8Array` 등) | `web/src/world/worldView.ts` — 서버 상태의 사본 |
| 서버 | Spring Boot 4 (Kotlin 2.3) + STOMP WebSocket | `server/` — 게임 로직 권위. 룸 스코프 토픽 |
| 도메인 코어 | `web/src/game/core.ts` ↔ `server/.../domain/GameCore.kt` | **1:1 미러**. 순수 함수 + 주입 시계 |
| 계정 DB | H2 (파일) + JPA | 계정·친구만(게임 월드와 분리) |
| 로그인 | Firebase(구글) | 선택 — 없으면 게스트로 전부 플레이 가능 |
| 경계 데이터 | `web/public/kr-sgg.geojson` / `server/.../resources/data/kr-sgg-cells.json` | 클라·서버가 같은 순서로 읽어 `admIndex` 정렬을 구조적으로 보장 |

**핵심 제약**: 셀 상태를 React state에 넣지 않는다. MapLibre 인스턴스는 1회 생성 후 명령형 갱신(dirty Set + rAF 배치). 게임 로직은 클라에서 돌리지 않는다 — 서버(개발 시엔 브라우저 내 목 서버)가 유일한 진실.

## 2. 데이터

- **소스**: `web/public/kr-sgg.geojson` — 시/군/구 250개, 속성 `sggcd`(5자리 = [시도2][시군구3])·`sggnm`·`sidocd`·`sidonm` 포함. 로더는 `web/src/data/loadMapData.ts`. 서버는 오프라인 전처리된 `kr-sgg-cells.json`(인접·경계·반경 precompute 포함)을 읽는다.
- **admIndex**: 로드 시 부여하는 0..N-1 조밀 인덱스. feature id(`promoteId`) 겸 상태 배열 인덱스. 클라·서버가 같은 파일을 같은 순서로 읽으므로 어긋날 수 없다.
- **인접 그래프**: TopoJSON 위상(`topojson.neighbors()`)으로 추출(클라). 서버는 전처리된 인접을 그대로 읽는다. 기하 기반 판정은 부동소수점 슬리버 때문에 쓰지 않는다.
- **아크(공유 경계선)**: TopoJSON 아크 단위로 국경선만 그린다(같은 소유주 내부 경계는 숨김). 시/도 경계는 정적 하이라이트.
- **섬**: 인접이 끊긴 별도 컴포넌트(울릉군·제주 등)는 일반 출정으로 도달 불가 — **공수부대**가 유일한 통로(§4.7).
- **특산물 플레이버**: `web/src/data/sggSpecialty.ts` — 시/군/구별 대표 특산물·명소를 선택 패널에 표시(밸런스 무관, 표시 전용).

## 3. 게임 상태 모델

### 3.1 셀 상태 (셀당 몇 바이트 + 정적 메타)
```ts
ownerId : Uint8Array   // 0 = 중립, 1~ = holderId
troops  : Uint16Array  // 현재 주둔 병력
troopCap: Uint16Array  // 병력 상한 (정적, 현재 전 셀 균일 BASE_CAP)
neighborIndex: number[][]  // 인접 그래프 (정적)
```

### 3.2 holderId 간접 계층
셀은 소유자를 `holderId`로 저장하고, 별도 테이블(`holders: Map<holderId, {name, paletteIdx, isAi}>`)이 이름·색·AI 여부를 든다.
- `0` = 중립 · `1~254` = **플레이어와 AI 공용**(사람 참가·AI 채우기가 같은 `allocateHolderId` 할당기를 공유) · `255` = 예약(구 환경 세력 E, 현재 미사용).
- **AI도 그냥 holder 하나** — 셀 배열·전투·이동·렌더 로직에 특수 분기가 없다. 차이는 "행동을 AI가 결정"과 `isAi` 플래그(생산 배율)뿐.
- 색: 8슬롯 최대 대비 팔레트를 **세션마다 셔플**해 배정(§4.12). `holder.paletteIdx`가 슬롯을 가리킨다.

### 3.3 Order (이동 유닛)
모든 병력 이동은 `Order {from, to, amount, holderId, departTick, arriveTick, path?, airdrop?}` 하나로 표현된다. 출발 시 출발지에서 즉시 차감 → 지도 위를 이동(거리 기반 시간) → 도착 시 전투/증원 판정. 출정·행군·공수·공격 큐·AI 확장 전부 같은 경로를 쓴다.

## 4. 게임 규칙

> 상수 이름만 표기하고 절대값은 적지 않는다(튜닝 중). 현재 값은 `web/src/config.ts`/`GameConfig.kt` 참조.
> 서버 tick은 **5Hz(200ms)**, 순위·도미네이션 판정은 1Hz.

### 4.1 병력 생산 (`tickProduction`)
- 중립이 아닌 소유 셀은 상한까지 자동 충전(`FILL_TO_CAP_SEC`). 상한 도달 시 정지, 초과분 없음.
- 상한은 현재 전 셀 균일(`BASE_CAP` — 인구 데이터 미보유 fallback).
- 생산 배율: 사람 1.0, **AI는 `AI_PROD_MULT`(약 0.7)로 약간 불리**.

### 4.2 출정 (`trySortie`, `tryMultiSortie`)
- **우클릭 드래그**(내 셀에서 화살표를 끌어 대상에서 놓기) 또는 우클릭으로 인접 셀에 출정. 보낸 병력(`floor(troops × SORTIE_RATIO)`, 비율은 HUD 슬라이더로 조절)은 **출발지에서 즉시 차감**되어 유닛으로 이동한다.
- **드래그 쓸기(multi-sortie)**: 내 셀에서 우클릭 드래그로 여러 인접 적·중립을 쓸면 병력을 **균등 분할해 동시 출정**.
- 증원(내 셀로 이동)은 대상의 **상한 여유분만큼만** 유효하다(초과분 소멸 방지).

### 4.3 이동·전투 판정 (`tickOrders` → `resolveArrival`)
- 이동 시간 = `clamp(중심거리 / UNIT_SPEED_DEG_PER_SEC, UNIT_TRAVEL_MIN_SEC, UNIT_TRAVEL_MAX_SEC)`.
```
대상 Y, 도착 병력 amount:
  아군    → Y.troops = min(Y.troops + amount, cap)     // 증원
  적/중립 → Y.troops -= amount
            0 미만이면 함락: Y.owner = 나, 남은 병력 주둔
```
- **정면충돌(`tickOrderClashes`)**: 같은 변을 반대 방향으로 지나는 두 유닛은 상쇄(작은 쪽 소멸, 큰 쪽은 차이만큼 계속). 미사일·전술핵은 착탄 셀 위의 이동 유닛도 파괴.

### 4.4 자동 행군 (`tryMarch`)
- 멀리 있는 **내** 셀을 우클릭하면 내 영토만 밟는 최단 경로(BFS, `MARCH_MAX_HOPS` 이내)로 릴레이 행군. 도중에 경로가 끊기면(셀 상실) 그 자리에서 일반 규칙으로 정착/전투한다.

### 4.5 공격 큐 (`toggleAttackTarget`, `tickAttackQueue`)
- 내 국경에 인접한 적·중립 셀을 **우클릭**하면 공격 큐에 등록(⚔️). 매 주기(`ATTACK_QUEUE_INTERVAL_SEC`)마다 그 대상에 인접한 내 셀 중 병력이 `ATTACK_QUEUE_MIN_TROOPS` 초과인 셀들이 `ATTACK_QUEUE_RATIO`만큼 자동 출정한다. 점령하거나 인접 셀을 모두 잃으면 자동 해제.

### 4.6 보급선 (`tickSupply`, `supplyTowardFronts`)
- 공격 큐 대상에 인접한 내 셀을 "전선"으로 보고, 후방 셀들이 매 주기(`SUPPLY_INTERVAL_SEC`) 병력 일부(`SUPPLY_RATIO`)를 **가장 가까운 전선 방향으로 한 홉씩** 자동 전진(다중 소스 BFS). 후방→전선 보급 파이프라인이 자동 형성된다(내 셀 사이만 흐르고 전투는 안 함).

### 4.7 공수부대 (`tryAirdrop`, `resolveAirdrop`)
- `Shift`로 조준 → ① 원으로 내 셀들 선택(클릭, 반경은 미사일과 동일) → ② 목적지 클릭. 선택 셀 병력을 최대 `AIRDROP_MAX_TROOPS`까지 **삼각형 유닛**으로 투하(초과분은 출발 셀에 남음).
- 도착 시 목적지부터 인접 BFS로 순차 flood — 적·중립은 전투로 점령, 내 셀은 상한까지 증원.
- 사거리 상한(`AIRDROP_MAX_RANGE_DEG`) + 플레이어당 쿨다운(`AIRDROP_COOLDOWN_SEC`). **일반 출정이 못 가는 섬에 가는 유일한 수단** — 출발지·목적지 중 하나가 사일로 섬(제주)이면 **사거리 무제한 예외**.

### 4.8 미사일 (`trySpawnMissile`, `launchMissile`)
- 전국 무작위 셀에 주기적으로 스폰(`MISSILE_SPAWN_SEC`, 시/도 균등 추첨, 맵 총량 상한 `MISSILE_MAX_TOTAL`). 🚀 마커.
- 미사일이 얹힌 셀의 **소유자**가 발사 가능: `Space`로 조준 → **단일 표적** 클릭 → 그 셀 중립화(병력 0). 미사일 1개 소모. 서버가 반경·근접을 재검증하며, 클라가 보낸 값은 신뢰하지 않는다.

### 4.9 전술핵 사일로 (제주) (`launchNuke`)
- **제주시(`NUKE_SILO_CODES = ["50110"]`)에 고정 사일로 1기**. 사일로 셀을 점령한 플레이어는 소모품 없이 **원 범위 광역** 미사일을 **`NUKE_COOLDOWN_SEC`마다** 발사한다(반경 = `MISSILE_RADIUS_DEG × NUKE_RADIUS_MULT`).
- 일반 미사일이 단일 표적인 것과 달리 전술핵은 **원에 걸친 여러 셀을 한 번에** 타격한다. 착탄 시 방어막 보호 셀만 피해에서 제외.
- 제주는 본토와 인접이 끊긴 컴포넌트라, **사일로 섬(제주)을 오가는 공수는 사거리 제한을 받지 않는다** — 본토에서 상륙전으로 뺏고 뺏기는 쟁탈 거점.

### 4.10 포위 귀속 (`tickAnnex`)
- 한 플레이어가 다른 **단일 실제 플레이어**의 영역을 자기 셀만으로 완전히 둘러싸고(바깥 탈출로 없음) `ANNEX_HOLD_SEC` 연속 유지하면 **그 영역 전체를 흡수**한다(병력 0으로 리셋). 실제 플레이어 2명 이상 필요, 방어막 보호 중인 소유자는 흡수 불가. 포위 대기 중인 셀은 반짝임으로 예고, 벽이 뚫리면 타이머 리셋.

### 4.11 스폰 방어막 (`applyShield`, `isShielded`)
- 신규 참가·AI 채우기·재시작 직후 `SPAWN_SHIELD_SEC` 동안 내 셀은 **원거리 즉사(미사일·전술핵 중립화)와 포위 귀속**으로부터 보호된다.
  - **미사일**: 보호 셀이 표적이면 **발사 자체가 거부**(미사일 소모 없음).
  - **전술핵**: 발사는 되고 **보호 셀만 착탄에서 제외**.
  - **포위 귀속**: 보호 중 소유자는 흡수 불가.
- **출정·행군·공수 같은 유닛 전투는 방어막과 무관하게 정상 진행** — 방어막은 원거리 즉사 수단만 막는다. 내 능동 행동엔 제한 없음. 보호 중엔 지도에 방어막 돔 표시.

### 4.12 AI 플레이어 (`fillAiPlayers`/`tickPlayerAi`, 서버 `PlayerAi`)
- 라운드 시작 시 사람 수가 `AI_FILL_TARGET`(8) 미만이면 부족분을 AI holder로 채운다(전국 최원점 샘플링으로 스폰). AI는 **미사일·전술핵·공수를 쓰지 않고**(연결이 없어 발사 불가) 매 주기(`AI_ACT_INTERVAL_SEC`) **확장(expand)**과 **증원(reinforce)**만 한다.
- **일부러 실력을 낮춘다**(완벽한 타이밍의 기계처럼 안 보이게):
  - `AI_HESITATE_CHANCE` — 매 주기 일정 확률로 아무 행동도 안 함(반응이 들쭉날쭉).
  - `AI_RANDOM_TARGET_CHANCE` — 가장 약한 대상 대신 이길 만한 인접 대상을 **아무거나** 고를 확률(비최적 공격).
  - `AI_ATTACK_MARGIN_JITTER` — 공격 마진(`AI_ATTACK_MARGIN`)을 판단마다 ±비율로 흔들어 과신중/무모를 섞음.
  - 후보 이동을 정렬하지 않고 **셔플**해 한정된 출정 횟수(`AI_MAX_SORTIES_PER_TICK`)를 늘 최선에만 쓰지 않게 함.
- 정원 초과로 사람이 난입하면 가장 약한 AI를 밀어내 자리를 만든다(`removeWeakest`).

### 4.13 색상 (8색 · 세션 셔플)
- 플레이어 색은 최대 대비 8색(레드·블루·그린·오렌지·퍼플·시안·핫핑크·옐로) — `PLAYER_PALETTE_IDXS = [1,2,3,4,5,7,8,9]`.
- 월드(세션/라운드) 생성 시 이 배열을 한 번 셔플(`playerPaletteBag`)하고 참가 순서대로 나눠 준다 → **8명까지 색이 겹치지 않고, 판마다 배정이 달라진다**. 채움은 저불투명도에서도 구분되도록 선명한 원색, 테두리(국경선·순위표 스와치)는 같은 색을 약간 어둡게 짝지었다.

### 4.14 궤멸과 재시작 (`respawnPlayer`)
- 내 셀이 0개가 되면 GAME OVER 오버레이 — **재시작**(새 시작 셀 배정 + 방어막) 또는 나가기. 자동 재배정은 없다(유저가 선택).

## 5. 라운드 · 승리 · 계급

### 라운드
- **즉시 승리(도미네이션)**: 한 명이 전국 `ROUND_WIN_RATIO`(51%) 이상 점유(1Hz 판정).
- **시간 종료**: `ROUND_DURATION_SEC`(30분) 도달 시 그 시점 1위 승리. HUD 상단에 라운드 타이머(마지막 1분 빨간 깜빡임).
- 종료 시 전원 결과 화면(우승자·최종 순위) → 대기실로. 로그인 유저의 전적(`gamesPlayed`/`wins`)이 갱신된다.

### 계급 (소유권에서 파생 — 저장하지 않고 매 프레임 계산, `computeRank`)
```
구청장 : 셀 1개 이상 소유 (기본)
시장   : 셀 MAYOR_RANK_CELLS(5)개 이상 소유
도지사 : 어떤 시/도(sidocd)의 모든 셀을 소유
대통령 : 전국 40%(PRESIDENT_WIN_RATIO) 이상 점유 — 가장 높은 계급, 달성 순간 당선 연출
```

판정은 **높은 계급부터** 훑어 먼저 맞는 것 하나로 정해진다(대통령 → 도지사 → 시장 → 구청장). 그래서
도지사 조건이 시장보다 먼저 걸린다 — 1셀뿐인 **세종**이나 2셀뿐인 **제주**를 장악하면 시장을 건너뛰고
바로 도지사가 된다.

## 6. 멀티플레이 (로비 · 방 · 서버 권위)

- **흐름**: 로비(공개 방 목록 + 초대 코드 입장) → 방 생성/입장 → 대기실(방장👑만 시작 가능, 나머지는 준비 토글) → 라운드 → 결과 → 로비.
- **방(Room)**: `LOBBY → PLAYING → ENDED → LOBBY` 상태기계. 한 방 = 독립 월드/라운드. 방은 **휘발성**(스냅샷 영속 없음) — 서버 재시작·라운드 종료 시 월드는 새로 만든다. 상한: 방 32개, 동시 진행 방 8개, 방당 인원 8명.
- **서버 권위**: 모든 게임 로직(생산·전투·AI·타이머)은 서버 `GameLoop`(단일 스레드, 5Hz)가 실행. 클라 명령은 STOMP로 전송하고 서버가 검증(비율·반경·쿨다운은 클라 값을 신뢰하지 않음). 락 없이 "한 스레드만 월드를 건드린다"는 구조로 경합 차단.
- **프로토콜**([docs/api-spec.md](docs/api-spec.md), `web/src/net/protocol.ts`): 입장 시 `WELCOME`(전체 스냅샷 1회) → 이후 `DELTA`(변경 셀만, 5Hz) + `LEADERBOARD`(1Hz). **룸 스코프 토픽**(`/topic/room/{id}/world|leaderboard|state`), 로비는 `/topic/rooms`.
- **재접속**: `token`(라운드 신원)·`clientId`(방장/재입장 신원)로 복구. 하트비트(10s)로 끊김 감지 → 자동 재연결 + "연결 끊김" 배너.
- **로그인·친구**: 구글 로그인(Firebase, 선택)으로 전적·레벨·친구 기능 사용. 친구 접속 현황 기반 초대/따라가기. 미로그인 게스트도 게임 전부 플레이 가능.
- **목 서버**: `VITE_USE_LOCAL_MOCK=1`로 띄우면 브라우저 안에서 동일 `Connection` 계약의 목 서버(`localConnection`)가 돌아 서버 없이 솔로 플레이·개발 가능(로비를 건너뛰어 바로 시작).

## 7. 렌더링 · 입력

### 렌더링 (`web/src/map/MapView.tsx`)
- 소유권 색칠은 `setFeatureState`(paint 전용) + dirty Set + rAF 배치. 국경선은 아크 단위(소유주가 다른 경계만), 굵기는 줌 비례.
- 함락 플래시·미사일 폭발 충격파·방어막 돔·이동 유닛(원/삼각형) 보간·포위 예고 반짝임 등 이펙트는 rAF 루프에서 갱신.
- 셀 이름·병력 숫자는 포인트 소스 + 충돌 배치. 저줌(줌 7 미만)에선 소유 점 + 플레이어 닉네임만, 그 이상에선 셀 이름 + 병력 배지로 전환.

### 입력 (데스크톱)
| 입력 | 동작 |
|---|---|
| 좌클릭 | 셀 선택 / 조준 중 발사·투하 (빈 곳 = 해제) |
| 우클릭 (짧게) | 인접 적·중립 셀을 공격 큐에 등록/해제 (⚔️) |
| 우클릭 드래그 | 내 셀에서 출정 · 여러 목표 쓸기 · 먼 내 셀로 자동 행군 |
| `WASD`/방향키 · `Q E +/-` | 연속 이동 · 줌 (동시 입력 가능) |
| `Space` | 미사일 조준 토글 |
| `Shift` (좌/우) | 공수부대 토글 |
| `Esc` | 조준/수송 취소 |
- 키 입력은 `e.code`(물리 키) 사용 — 한글 IME 간섭 방지.

## 8. 튜닝 상수

모든 밸런스 값은 **`web/src/config.ts`의 `CONFIG` 객체 한 곳**에 모으고, 서버 `GameConfig.kt`가 1:1로 미러한다(`@JsonProperty` 와이어 키가 SCREAMING_SNAKE로 클라 키와 동일). **서버가 원본**이며, 입장 시 `WELCOME.config`로 클라에 전달된다. 운영 중 `POST /admin/config`로 부분 갱신 가능.
주요 노브: 충전 속도·상한 · 라운드 승리/시간 · 출정 비율 · 공격 큐/보급 주기·비율 · 미사일 스폰/반경/총량 · 전술핵 배수/쿨다운 · 공수 사거리/쿨다운/수송량 · 포위 유지 시간 · 방어막 시간 · AI 목표 인원/공격성/랜덤성. **절대값은 튜닝 중이라 이 문서에 적지 않는다.**

## 9. 실행 방법

```bash
# 클라만 (서버 없이 목 서버로 솔로 플레이)
cd web && VITE_USE_LOCAL_MOCK=1 npm run dev      # http://localhost:5173

# 풀스택 (멀티플레이)
cd server && ./gradlew bootRun     # :8080 (STOMP /ws, REST /api·/admin)
cd web && npm run dev              # :5173 → localhost:8080에 자동 연결
```
- 다른 서버 주소로 붙일 땐 `VITE_WS_URL=ws://<host>:8080/ws/websocket npm run dev`, REST는 `VITE_API_URL`.
- **구글 로그인(선택)**: `web/.env.local`에 `VITE_FIREBASE_*` 4종, `server/secrets/firebase-service-account.json` 배치. 없으면 게스트로 동작.
- **단일 jar 배포**: `cd server && ./gradlew deployJar` → `java -jar build/libs/server-*-deploy.jar` (웹 정적 빌드까지 한 jar가 :8080에서 서빙, 단일 오리진). 자세한 배포(Docker/GHCR/watchtower)는 [docs/architecture.md](docs/architecture.md) §7.
