# 실제 지도 기반 지속형 영토 점령 PvPvE 게임(동대장 시뮬레이터) — 개발 사양서

> **이 문서의 용도**: Claude Code가 목업/프로토타입을 구현할 때 참조하는 사양서.
> 서술형 기획 의도가 아니라 "무엇을 만들지"에 초점.
> 레퍼런스: 실제 한국 행정동 지도 위의 r/place(지속형 캔버스) × state.io(영토 점령) + 문명의 야만인 같은 소규모 환경 세력(초반 PvE 긴장).
>
> **PvPvE**: 게임의 축은 플레이어 간 영토 경쟁(**PvP**). **환경 세력(E)**은 문명 게임의 야만인처럼, 혼자 플레이하거나 아직 다른 플레이어와 마주치지 않은 **초반에 긴장감을 주는 조연**이다.
> **E는 상한이 있어 플레이어를 넘어서 맵을 장악하지 못한다** — 존망을 건 위협이 아니라 초반 워밍업 상대. 상세 규칙은 §4.6.

## 0. 지금 만들 것 (목업 범위)

**목표**: 전국 행정동 지도를 렌더링하고, 병력을 출정시켜 인접 동을 점령하며, **초반 긴장 요소인 소규모 환경 세력(E)과 싸우는** 오프라인 플레이가 되는 목업.

이 목업은 아래 **마일스톤 1~2**에 해당한다. 서버·WebSocket·계정은 **넣지 않는다**. 로컬 상태(브라우저 메모리)만으로 게임 감각과 수치를 확정하는 것이 목적. E가 있어야 오프라인에서도 상대가 있는 플레이가 성립하므로 **E AI는 목업 범위에 포함**한다.

```
목업에 포함        : 지도 렌더 · 동 소유권 색칠 · 선택/출정 입력 · 인접 판정 · 병력 생산/상한 · 소유권 전환 · 유닛 이동 · 환경 세력(E) AI · 계급 계산
목업에서 제외(후순위): WebSocket · 서버 권위 · 게스트 세션 · 리셋 · 명예의전당 · 팀전
```

## 1. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 빌드 | Vite + TypeScript | |
| 지도 | MapLibre GL JS | feature-state 필수 |
| UI 상태 | Zustand | 소량만 (선택 동, HUD) |
| 게임 상태 | 순수 `Uint8Array` (또는 typed array) | **React 밖**. 라이브러리 없음 |
| 스타일 | Tailwind 또는 CSS Modules | 자유 |
| 경계 데이터 | 법정동 GeoJSON (`web/public/beopjeong-emd.geojson`, gisdeveloper SHP를 mapshaper로 변환한 정적 자산) | WGS84·UTF-8. 클라·서버가 이 파일 하나를 공유해 admIndex 정렬을 구조적으로 보장(architecture.md §4) |

**핵심 제약**: 3,500개 동 상태를 React state에 넣지 말 것. 델타마다 전체 재조정이 발생한다.
MapLibre 인스턴스는 `useRef`에 담아 `useEffect`에서 1회만 생성, 이후 React는 지도를 직접 건드리지 않는다.

## 2. 데이터

### 2.1 경계 데이터
- 소스: gisdeveloper 법정동(읍면동) SHP를 mapshaper로 WGS84 GeoJSON 변환해 `web/public/beopjeong-emd.geojson`로 커밋(대용량 원본 SHP는 미커밋). 클라(`fetch`)와 서버(`readFileSync`)가 **같은 파일**을 같은 필터·순서로 읽어 admIndex를 매긴다 — 정렬이 어긋날 수 없는 구조(architecture.md §4).
- 각 feature의 8자리 법정동코드 `EMD_CD` = `[시도 2][시군구 3][읍면동 3]`.
- MapLibre 소스에 `promoteId: 'admIndex'` 지정(로드 시 부여하는 0..N-1 조밀 인덱스, feature id 겸 상태 배열 인덱스로 사용).

### 2.2 파생 레이어
- 시군구 집계: `EMD_CD.slice(0,5)` 기준 그룹핑. **서버 없이 클라이언트에서 계산**. mapshaper dissolve로 시군구 지오메트리 별도 생성 가능.
- 인접 그래프: **TopoJSON의 위상 정보로 추출** (`topojson.neighbors()`). GeoPandas `touches()` 류의 기하 기반 판정은 부동소수점 슬리버로 틀리므로 쓰지 말 것.

### 2.3 예외 처리 · 범위
- 섬·월경지(비연결 폴리곤, MultiPolygon): 인접 차수 0인 노드는 **페리 엣지 수동 추가 또는 시즌에서 제외** — 전국 데이터 전환 시점에 실측해 결정.
- **범위 확정: 전국 전체(~3,500동)**. 서울 424동은 초기 목업 검증용이었고, 데모는 전국으로 간다. 로더는 시도 필터만 바꾸면 되는 구조를 유지한다(성능 문제 시 서울 폴백 가능).
- 전국에서는 §7.2 **줌별 점진 공개**(낮은 줌 시군구 집계, 라벨 상한)가 선택이 아니라 실사용 요건이 된다.

## 3. 게임 상태 모델

### 3.1 동(cell) 상태 — 동당 3바이트
```ts
// 인덱스 = admIndex (adm_cd 정수 변환값 → 0..N-1 로 매핑한 조밀 인덱스 권장)
ownerId : Uint8Array   // 0 = 중립, 1..255 = holderId
troops  : Uint16Array  // 현재 주둔 병력 수
// 상한/생산은 정적 메타에서 조회 (아래 3.3)
```
전국 약 3,500동 → 약 10.5KB. **React 외부**에 두고, 변경 시 dirty Set에 admIndex 추가.

### 3.2 holderId 간접 계층 (중요 — 팀전 확장 이음매)
동은 소유자를 개인 ID로 직접 저장하지 않고 **`holderId`**로 저장한다. 별도 조회 테이블로 분리:
```ts
holders: Map<holderId, { name, fillColorIdx, strokeColorIdx }>
// 개인전: holderId = 플레이어 ID
// 팀전(v2): holderId = 팀 ID  ← 이 구조 덕분에 동 배열/렌더/집계 로직 불변
// 환경 세력(PvPvE): holderId = ENV_HOLDER_ID(255, 예약) ← E도 그냥 holder 하나.
//   동 배열·전투·이동·렌더 로직에 E 특수 분기 없음. 차이는 "행동을 AI가 결정"뿐 (§4.6).
```

### 3.3 정적 메타 (동별, 게임 중 불변)
```ts
troopCap    : Uint16Array  // 병력 상한 (인구 정규화, 3.4)
neighbors   : number[][]   // admIndex → 인접 admIndex 목록 (TopoJSON에서 1회 계산)
centroid    : [lng,lat][]  // polylabel 로 계산 (병력 배지/숫자 위치용, centroid 아님 주의)
```

### 3.4 병력 상한 = 인구 정규화 (확정 공식)
```
troopCap[i] = round( BASE * clamp( log(pop[i] / medianPop) * K + 1, 0.7, 1.5 ) )
```
- `medianPop` 기준 로그 압축. 실제 인구 50배 차 → 상한 약 2배(0.7~1.5)로 완화.
- `BASE`, `K`는 **튜닝 상수** (아래 5장). 초기값으로 시작해 플레이하며 조정.
- pop 데이터가 없으면 목업 1차에서는 전 동 `troopCap = BASE` 균일로 시작해도 됨(공식은 자리만 잡아둠).

## 4. 게임 규칙 (구현 대상)

### 4.1 병력 생산
- **접속 중인 소유자의 동만** 병력이 상한까지 차오른다. (목업 오프라인에서는 "내 동 전부 생산"으로 간주)
- 충전 속도: 빈 동(0) → 상한까지 **약 3분**. 즉 `troopsPerSec = troopCap / 180`.
- 상한 도달 시 정지, 초과분 없음. (이 규칙이 능동 플레이 강제 + 스노우볼 억제의 핵심)
- 구현: `requestAnimationFrame` 루프에서 경과 시간만큼 증가시키되, 매 프레임 3,500개를 순회하기보다 **마지막 갱신 tick 기반 lazy 계산**(조회 시점에 경과분 반영) 권장.

### 4.2 출정 (핵심 액션)
```
입력: 내 소유 동 X 를 탭/클릭
전제: X.owner == me  &&  X.troops > 0
동작:
  1. amount = floor(X.troops / 2)          // 절반 출정
  2. 대상 선택: X 에 인접한 동 중 하나 (UI: 두 번째 탭 또는 드래그. 4.5 참조)
  3. X.troops -= amount
  4. 즉시 전투 판정 (4.3)
```
- **쿨다운 없음**. 병력이 있으면 언제든.
- 전선 제한: 대상은 **X에 인접한 동만**. 원거리 불가.

### 4.3 전투 판정 (즉시)
```
대상 Y, 출정 병력 amount:
  if Y.owner == me:                 // 아군 → 병력 이동(증원)
      Y.troops = min(Y.troops + amount, Y.cap)
  else:                             // 적/중립 → 전투
      Y.troops -= amount
      if Y.troops < 0:              // 함락
          Y.owner  = me
          Y.troops = -Y.troops      // 남은 병력이 주둔
      // Y.troops >= 0 이면 소유권 유지, 병력만 감소
```
- 중립 동 초기 방어 병력은 **낮게** (초반 확장 쉽게). 튜닝값.

### 4.4 Order 객체 (유닛 이동 확장 이음매 — 지금은 즉시 처리)
출정을 즉시 실행하지 말고 **명령 객체로 표현**한 뒤 처리한다. 지금은 즉시 도착이지만, 이 한 겹이 향후 유닛 이동 체제 전환을 공짜로 만든다.
```ts
interface Order { from:number; to:number; amount:number; departTick:number; arriveTick:number; }
// 목업(절충형): arriveTick = departTick  → 큐에 넣자마자 apply
// v2(유닛이동)  : arriveTick = departTick + dist(from,to)/speed → arriveTick 도달 시 apply, 그동안 Canvas 렌더
```
전투 판정 로직(4.3)은 두 모드에서 **동일**. 바뀌는 건 "언제 apply 하느냐"뿐.

### 4.5 입력 방식
- **데스크톱 (확정, 구현됨)**: **좌클릭 = 동 선택**(빈 곳 클릭 = 해제) · **우클릭 = 선택한 내 동에서 인접 동으로 이동/출정**. 더블클릭 줌·우클릭 회전은 비활성.
- **모바일**: 탭 = 선택, 하단 큰 버튼 = 실행 (오발 방지). 목업에서는 데스크톱 우선, 모바일은 후순위.
- 키 입력은 **`e.code`(물리 키)** 사용 — 한글 IME에서 `e.key`는 단축키를 죽임. `e.isComposing || e.keyCode===229` 필터.
- 이동/줌은 여러 별칭 수용: 이동 `WASD`+방향키 / 줌 `+ - = Q E`(주의: `+`의 code는 `Equal`).
- 키보드 없이 100% 플레이 가능해야 함(가속 장치일 뿐).

### 4.6 환경 세력 (E) — 초반 긴장용 조연 (문명의 야만인 모델)

E는 지도를 잠식하는 거대 위협이 **아니다**. **문명 게임의 야만인**처럼, 혼자 플레이하거나 아직 다른 플레이어와 마주치지 않은 초반에 "칠 대상"을 줘서 긴장감·워밍업을 제공하는 조연이다. **E는 상한이 있어 절대 플레이어를 넘어 맵을 장악하지 못한다.** (이게 이 요소의 정체성 — 세지지도, 끝없이 커지지도 않는다.)

- **정체**: 단일 AI holder(`ENV_HOLDER_ID = 255` 예약, §3.2). 동 상태·생산·출정·이동·전투 규칙은 플레이어와 **동일** — 차이는 (1) 행동을 AI가 결정, (2) 아래 **상한**이 걸린다는 것뿐.
- **시작**: 외곽 동 중 `ENV_START_CELLS`개 보유로 시작(외곽 = 지도 바깥과 맞닿은 동). 초반 플레이어 근처에 "칠 만한 적"이 있게 하려는 것.
- **상한 (핵심 규칙)**: E가 보유한 동 수 `envCells`는 항상 다음을 **모두** 만족한다. 하나라도 걸리면 **E는 확장 공격을 멈추고** 방어/자리 유지만 한다.
  - `envCells ≤ round(ENV_MAX_RATIO × 전체 동 수)` — 절대 하드 상한. 이 이상 커질 수 없다.
  - `envCells ≤ max(ENV_MIN_PRESENCE, 최대 플레이어 점유 동 수)` — **never-surpass**. 최강 플레이어보다 커지지 않는다(아무도 크지 않은 극초반엔 최소 존재감 `ENV_MIN_PRESENCE`까지만 허용).
  - **램프 없음** — 시간이 지나도 배율/상한이 오르지 않는다. 규모는 위 상한이 잡고, 세기는 그대로다.
- **생산**: 플레이어와 같은 충전 규칙 × `ENV_PROD_MULT`(기본 1.0, 분당 증가 없음). E는 항상 접속 상태로 취급(상시 생산).
- **행동 AI (규칙 기반, 목업)**: `ENV_ACT_INTERVAL_SEC`마다 1회, **상한에 여유가 있을 때만** 확장을 시도:
  1. E 보유 동 중 병력 최다 동 X 선택
  2. X의 인접 동 중 병력 최소 동 Y 선택 (플레이어/중립 구분 없음)
  3. `floor(X.troops × SORTIE_RATIO) > Y.troops × ENV_ATTACK_MARGIN` 일 때만 출정 (자살 공격 방지)
  - 출정·유닛 이동·전투 판정은 플레이어와 같은 Order 경로(§4.4)를 그대로 사용. 상한에 도달하면 이 확장 로직을 건너뛴다.
- **토벌 보상 (E를 칠 유인)**: E 동을 함락하면 주둔 병력에 `ENV_BOUNTY` 보너스. 초반에 E를 정리하면 이득 → 자연스러운 워밍업 동기.
- **소멸 가능**: 플레이어가 E 동을 전부 함락하면 E는 그 시즌에서 사라진다(재스폰 없음, 목업 기준). "야만인 소탕 완료" 상태. *(추후: 둥지/캠프에서 재스폰하는 버전 고려)*
- **전멸 리셋 없음**: E는 맵을 장악할 수 없으므로 E발(發) 시즌 종료 조건은 두지 않는다. (플레이어 50% 점유 리셋은 별개로 유지)
- **순위/계급과의 관계**: E는 순위표에 끼지 않는다. 계급(§6)은 플레이어에게만 적용.

## 5. 튜닝 상수 (한 곳에 모을 것)

```ts
export const CONFIG = {
  FILL_TO_CAP_SEC: 180,     // 빈 동 → 상한 충전 시간(초)
  BASE_CAP: 50,             // 병력 상한 base (튜닝)
  CAP_K: 0.4,               // 인구 정규화 압축 강도 (튜닝)
  CAP_MIN_MULT: 0.7,
  CAP_MAX_MULT: 1.5,
  NEUTRAL_TROOPS: 10,       // 중립 동 방어 병력 (튜닝, 낮게)
  SORTIE_RATIO: 0.5,        // 출정 비율 (절반)
  RESET_OWN_RATIO: 0.5,     // 전국 50% 점유 시 시즌 리셋 (목업 제외, 값만 명시)

  // 환경 세력 (PvPvE, §4.6) — 초반 긴장용 조연(문명 야만인). 전부 튜닝값.
  ENV_HOLDER_ID: 255,       // E 전용 holderId (예약)
  ENV_START_CELLS: 3,       // 시작 시 E 보유 동 수 (외곽에서 선정)
  ENV_PROD_MULT: 1.0,       // E 생산 배율 (기본 = 플레이어와 동일, 램프 없음)
  ENV_ACT_INTERVAL_SEC: 6,  // E 행동 주기
  ENV_ATTACK_MARGIN: 1.2,   // 이길 만할 때만 공격 (자살 방지 계수)
  ENV_BOUNTY: 10,           // E 동 함락 시 보너스 병력
  ENV_MAX_RATIO: 0.04,      // E 보유 동 수 하드 상한 (전체 대비 비율) — 절대 초과 못함
  ENV_MIN_PRESENCE: 4,      // 아무도 크지 않은 극초반의 E 최소 존재감(동 수)
};
```
> 모든 밸런스 값은 이 객체 한 곳에. 절대값은 **마일스톤 2에서 플레이하며 확정**. 지금은 위 초기값으로 시작.

## 6. 계급 (소유권 파생 — 저장하지 않고 계산)

```
동장   : 소유 동 수 >= 1
시장   : 어떤 시군구(adm_cd 앞 5자리)의 모든 동을 소유
도지사 : 어떤 도(앞 2자리)의 모든 시군구를 석권  (명목상)
```
- 소유권 변경 시 해당 holder의 계급 재계산. 승급/강등 이벤트·상태 저장 불필요(잃으면 자동 강등).
- 표현: 칭호 + 지도 배지(완전점령 시군구 위 왕관+이름). 승급 시 토스트.
- **계급 이점 = 광역 출정(조작 편의만)**: 완전점령 시군구는 한 번의 조작으로 그 시 모든 동에서 인접 전선으로 동시 출정. **단, 대상 동 수만큼 각 동 병력을 개별 소모 → 총 화력은 개별 출정과 동일**(스노우볼 없음). 목업에서는 후순위.

## 7. 렌더링

### 7.1 소유권 색칠
- `map.setFeatureState({source:'dong', id:admIndex}, {owner, troops})`.
- **채움색** `fill-color`: holder의 `fillColorIdx`(12색 팔레트, 영토에 고정, 겹침 허용).
- **테두리색** `line-color`: holder의 `strokeColorIdx`. 채움×테두리 조합으로 수십 명 구별. 정확한 소유자는 클릭 시 이름.
- 저대비 조합(예: 남색 채움+검정 테두리)은 팔레트에서 사전 배제.
- **환경 세력(E) 전용 색**: 어떤 플레이어와도 혼동되지 않는 팔레트 밖 색(독성 녹색/보라 계열)을 E에 고정 배정. "여긴 야만인 구역"이 지도만 봐도 구분돼야 한다. (E는 소규모이므로 지도에서 차지하는 면적은 작다.)

### 7.2 줌별 점진 공개
| 줌 | 표시 |
|---|---|
| 전국(낮음) | 시군구 집계 색 (경계선 약하게) |
| 권역(중간) | 동 경계 등장 |
| 근접(높음) | 병력 수 숫자 배지 |
- 시군구↔동은 `fill-opacity`를 줌 기반 `interpolate`로 크로스페이드.
- **병력 숫자는 근접 줌에서 화면에 보이는 것만** 별도 포인트 소스로 `setData` (수십 개). 3,500개를 text로 넣지 말 것.
- **주의**: feature-state는 **paint 속성 전용**. `text-field`(layout)에서는 못 읽음. 그래서 병력 숫자는 포인트 소스 방식으로.
- 병력의 시각적 강약은 `fill-opacity`를 `['feature-state','troops']`에 interpolate 해 표현 가능(paint라 됨).

### 7.3 성능
- 델타/변경은 **dirty Set + rAF 배치**. 한 프레임에 같은 동이 여러 번 바뀌어도 `setFeatureState` 1회.
- 병력 유닛 이동 점(향후)은 SVG 아닌 **Canvas 오버레이**.

## 8. UI 표면 (목업 최소)

- 지도(전체 화면).
- 선택 동 패널: 동 이름 · 소유자 · 병력/상한.
- 병력 HUD: 선택 동에서 지금 보낼 수 있는 양(절반) 표시. (쿨다운 없으므로 "병력 수"가 핵심 지표)
- 순위표: holder별 점유 동 수. (0접속 첫 화면 정책의 핵심 요소) — E는 순위에 끼지 않음.
- **E 잔존 표시**: 남은 E 동 수를 작게 표기(또는 지도 표시로만). E는 맵을 장악할 수 없으므로 **"전멸 위험도" 게이지는 두지 않는다.** 소탕 완료 시 "야만인 정리됨" 정도로만.
- 최근 점령 로그: "N초 전 · OO동 → 이름". E의 침공/플레이어의 토벌도 같은 로그에 흐름. append-only 이벤트 배열에서 파생.
- 범례: 팔레트 (+ E 전용 색).

## 9. 마일스톤 (목업 진행 순서)

1. **색칠된 지도** — 하드코딩 소유권 배열로 전국(또는 서울) 동 렌더. `promoteId`·feature-state·렌더 성능 검증. *(서버 없음)*
2. **오프라인 플레이** — 선택/출정 입력·인접 판정·병력 생산/상한·유닛 이동·전투/소유권 전환·**환경 세력 AI(§4.6)**·계급 계산. **여기서 게임 감각과 CONFIG 수치 확정.** *(서버 없음)*
3. *(목업 이후)* 온라인: WebSocket·스냅샷·델타·재접속. E tick은 서버 권위로 이관.
4. *(목업 이후)* 줌 전환·병력 숫자.
5. *(목업 이후)* 다듬기: 모바일 버튼·로그·로딩.

> **1→2까지가 이번 목업.** 2가 끝나면 서버 없이 혼자서도 E와 싸우며 플레이되는 물건이 나온다.
