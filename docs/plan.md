## 1. 최종 목표 (Definition of Done)

**여러 명이 각자 브라우저로 접속해 하나의 전국 지도에서 실시간으로 경쟁하는 PvPvE 데모.**

데모 시나리오 (6일차에 이것이 되면 성공):

1. 청중이 URL 접속 → 닉네임 입력 → 지도 위 자기 색 영토 하나를 받고 시작
2. 좌클릭 선택 / 우클릭 출정으로 인접 동을 점령, 다른 참가자와 국경에서 충돌
3. 초반/솔로 구간엔 소규모 환경 세력(E, 문명 야만인 모델)이 주변에서 소소한 위협 — 상한이 있어 맵을 장악하진 못하고, 잡으면 토벌 보너스. 순위표는 실시간 갱신(E는 순위 제외)
4. 새로고침해도 세션 유지(같은 영토로 복귀), 늦게 들어온 사람도 즉시 현재 판에 합류

## 3. 아키텍처 전환 (목업 → 온라인)

**원칙: 게임 로직의 진실은 서버(Kotlin) 하나에만 둔다.** 목업의 TS 게임 로직(`web/src/game/state.ts`)을 서버로 이식하고, 클라이언트는 **렌더러 + 입력 전송기**로 축소한다. 로직을 TS/Kotlin 양쪽에 이중 유지하지 않는다 (불일치 버그의 최대 원천).

```
[브라우저 (기존 web/)]                    [Spring Boot 서버]
  MapLibre 렌더 · HUD                       월드 상태 (ownerId/troops 배열)
  좌/우클릭 → SORTIE 명령 전송     ──────▶   명령 검증 (소유/인접/병력)
  스냅샷/델타 수신 → feature-state 반영 ◀──   tick 루프: 생산 · Order 도착 처리 · E AI
  유닛 원 보간 (departTick~arriveTick)       주기 브로드캐스트 (STOMP /topic/world)
```

### 프로토콜 (Day 1에 동결, 이후 불변)

| 방향 | 메시지 | 내용 |
|---|---|---|
| C→S | `JOIN` | nickname, token(재접속 시) |
| S→C | `WELCOME` | holderId, 색, **전체 스냅샷**(ownerId·troops 배열, holders 목록, 진행 중 orders) |
| C→S | `SORTIE` | from, to |
| S→C | `DELTA` (5Hz) | 변경된 동만 `[admIndex, owner, troops]`, 새 order(from,to,amount,departTick,arriveTick), 로그 이벤트 |
| S→C | `LEADERBOARD` (1Hz) | 순위 + E 점유율 |

- 전국 ~3,500동 전체 스냅샷도 raw ≈ 10.5KB(JSON ≈ 수십 KB) → 접속 시 1회이므로 JSON으로 충분, 바이너리 최적화 불필요. DELTA는 변경분만이라 규모 무관.
- 시간 동기화: 서버 타임스탬프 기준. 클라는 offset 1회 추정해 유닛 보간에 사용.

| | 서버 담당 (S) | 클라 담당 (C) |
|---|---|---|

- E AI·전투·생산의 룰 자체는 이미 README §4에 확정 — 구현 순서만 남음.

## 5. 일자별 계획

### Day 1 — 프로토콜 동결 + 양쪽 뼈대
- **공통(오전)**: 프로토콜 스키마·CONFIG 전달 방식 확정. Kotlin/Java 결정. 이후 스키마 변경은 양측 합의로만.
- **S**: Spring Boot 프로젝트 셋업, STOMP 에코 확인. **전국** 경계 데이터(인접 그래프·동 메타)를 서버에서 로드 — 목업의 topojson 산출물을 JSON으로 추출해 리소스로 포함.
- **C**: **전국 데이터 전환** — 로더의 시도 필터 제거, 전국 ~3,500동 렌더 성능 측정(아크 국경 포함), 인접 차수 0인 섬 목록 실측 → 페리 엣지/제외 방침 결정. 목업 리팩터 — `game/state.ts` 직접 호출을 걷어내고 "상태 반영 계층"(스냅샷/델타 적용 함수)으로 재구성. 접속 화면(닉네임 입력) 추가.
- **끝나면**: 서버 띄우고 클라가 WELCOME 스냅샷을 받아 **전국 지도**에 색이 칠해진다 (정적).

### Day 2 — 서버 권위 게임 루프
- **S**: 월드 tick 구현 — 병력 생산(lazy), SORTIE 검증(소유·인접·병력>0), Order 큐·arriveTick 도착 판정·전투(README §4.3 그대로), DELTA 브로드캐스트.
- **C**: SORTIE 전송, DELTA 적용(dirty→feature-state), 서버 order 기반 유닛 원 보간. 토스트/에러 표시.
- **끝나면**: 브라우저 2개로 서로 다른 색 영토가 실시간 전투한다. **온라인 PvP 성립.**

### Day 3 — E 세력 + 세션
- **S**: E AI(README §4.6): 외곽 스폰, 행동 주기, 최다병력→최소병력 인접 공격, **상한(ENV_MAX_RATIO·never-surpass) 넘으면 확장 중단**, 토벌 보너스, 전부 함락 시 소멸. 램프·전멸 리셋 없음. 게스트 토큰 재접속 복구(holderId 유지), 신규 참가자 시작 동 배정(기존 영토와 겹치지 않는 중립 동, **전국에 분산 — 수도권 쏠림 방지**).
- **C**: E 전용 색·범례, E 잔존 표시(점유율 게이지 아님), 침공/토벌 로그, 재접속 흐름. 순위표 서버 데이터로 전환.
- **끝나면**: **PvPvE 성립** — 초반엔 주변 E가 소소한 긴장을 주지만 맵을 먹지는 않고, 새로고침해도 내 영토가 남아 있다.

### Day 4 — 통합 테스트 + 밸런스 1차
- **공통**: 인원 모아 5~10명 동시 접속 플레이테스트 (madCamp 동료 동원). 발견 버그 즉시 수정.
- **S**: 동시성 검증(명령 경합, tick과 명령 처리 순서), 끊김/재접속 엣지 케이스, CONFIG 튜닝 반영(ENV_* 포함).
- **C**: 테스트에서 나온 UX 문제 수정 — 시작 위치 카메라 이동, 내 영토 강조, 함락 연출(플래시) 등.
- **끝나면**: 10인 동접에서 30분 세션이 큰 문제 없이 돈다.

### Day 5 — 배포 + 폴리싱 (+ 스트레치)
- **S**: 실서버 배포(클라우드 VM 또는 교내 서버) — 클라 정적 빌드를 Spring이 서빙(단일 origin, CORS 회피). 도메인/포트 확정. 서버 재시작 시 월드 스냅샷 저장/복구(파일이면 충분).
- **C**: 폴리싱 — 온보딩 문구, 승급 토스트(계급), 사운드(선택), 로딩 화면. **스트레치**: 모바일 터치 입력(탭 선택 + 하단 출정 버튼).
- **끝나면**: 외부 URL로 아무나 접속 가능한 상태. 밸런스 2차 튜닝.

### Day 6 — 프리즈 + 발표 준비
- **오전 코드 프리즈** (치명 버그만 수정). 데모 리허설 2회 — 청중 동시 접속 시나리오 포함.
- 발표 자료: 컨셉(PvPvE·실지도) → 라이브 데모 → 기술 포인트(서버 권위 tick·아크 국경 렌더·Order 이음매).
- 버퍼: 반나절. Day 4~5에서 밀린 항목은 여기서 흡수하되, **새 기능은 넣지 않는다.**
